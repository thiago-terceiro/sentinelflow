# SentinelFlow & SentinelPulse Workspace

Welcome to the **SentinelFlow & SentinelPulse** distributed systems workspace.

> [!NOTE]
> **Zero-Cost Architectural Constraint:** This project is deliberately built under a 100% free, open-source, and locally runnable constraint. All CI checks, static analysis (SonarJS, Ruff, Mypy), security audits, ML engines (ONNX Runtime CPU), and agent evaluation suites execute with zero paid SaaS dependencies.

### Core Systems Included

1. **📡 SentinelPulse: High-Throughput Real-Time SMS Fraud & Spam Intelligence Gateway**
   - **Target Role:** Traffic Intelligence & Communications ML (Tier-1 Telecom / Global CPaaS Messaging Infrastructure).
   - **Inference Latency & Boundaries:** Architectural target is synchronous inline ingress (`<15ms p95 end-to-end HTTP` target, `<0.1ms` warm in-graph ONNX C++ execution on short SMS) via compiled in-graph `TfidfVectorizer + CalibratedClassifierCV (LogisticRegression)` pipeline on AVX-512 CPU (measured raw `onnxruntime` `session.run()` microbenchmark latency is **0.032ms** / 32 µs on short SMS; zero GPU dependency). *Boundary & Evidence Status (`SF-015` 2,000-character maximum input contract):* The `<15ms` ReDoS guard applies specifically to `evaluate_heuristics()` (`p95 <= 3.477 ms`), and Boundary A internal `_process_single_message()` (`latency_ms`: `p95 = 1.937–2.129 ms` in-process agg / `1.748–3.725 ms` loopback in `e12734d`; `6.254–7.128 ms` agg / `5.488–8.815 ms` loopback in `cb64ff2`) is a separate internal timer that passes `<15ms` locally. Caller-observed HTTP round-trip latency (Boundary B) is a distinct measurement, and the **end-to-end HTTP `<15ms` target is NOT ESTABLISHED**: under identical harness boundaries, local loopback `concurrency=1` HTTP p95 passed in the `e12734d` run (`6.228–7.633 ms`) after exceeding 15 ms in the `cb64ff2` run (`17.259–17.793 ms`), while shared-event-loop `concurrency=4` (`25.280–26.094 ms` in `e12734d`; `60.852–61.257 ms` in `cb64ff2`) and `concurrency=8` (`54.984–63.106 ms` in `e12734d`; `121.061–124.160 ms` in `cb64ff2`) exceed 15 ms and mix FastAPI/Pydantic/post-timer `JsonFormatter` overhead with single-process queuing. Existing local loopback and single-loop results do not represent independent clients, multiple OS workers, or production traffic; real Redis network latency, production-scale load, and independent multi-worker behavior remain **unmeasured / unverified**.
   - **Velocity Counters:** Standalone Redis (`redis:7-alpine`) sliding-window sorted set aggregation (10s, 60s, 1h) using non-transactional single round-trip pipelines with 30s in-memory deque fail-open fallback (real Redis network behavior and production Redis deployment have not been validated; Redis Cluster remains future scope).
   - **MLOps Drift Telemetry & Escalation Review:** Kolmogorov-Smirnov (KS) two-sample test (feature drift) and Population Stability Index (PSI, prediction drift) paired with asynchronous escalation of ambiguous `FLAG` (`0.40–0.75`) disputes into SentinelFlow for human-in-the-loop review (`interrupt()`). Model retraining remains manual/offline via `train_onnx_model.py` (automated closed-loop active-learning retraining is future enterprise scope).
   - **Load Testing & Simulation:** Locust load-testing suite configured for 1,000–5,000 RPS and standalone telecom traffic generator (dev/simulation tooling only; does not establish production throughput).
   - **Full-Stack Live Dashboard:** Next.js console with real-time SSE streaming, live throughput gauge, color-coded latency percentiles, and interactive SMS tester.
   - **System Design Deep Dive:** [SYSTEM_DESIGN.md](./sentinelflow/SYSTEM_DESIGN.md) covers implemented gateway internals alongside future enterprise scaling designs (100k RPS Kafka partitioning, multi-node Redis Cluster slot compatibility).

2. **⚡ SentinelFlow: Autonomous Dispute Investigation & Cryptographic Audit Ledger**
   - **Architecture:** Human-in-the-loop LangGraph workflow with deterministic compliance/risk services, parallel `asyncio.gather` tool sessions, token-by-token `reasoning_delta` streaming, client-side time-travel state scrubbing (`?step=`), semantic iteration diffs (`?diff=1`), sticky cross-panel citation pinning (`?evidence=`), and PostgreSQL persistence.
